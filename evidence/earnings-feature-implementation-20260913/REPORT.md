# Aggregate earnings-change feature and selection implemented

Previous phase made progress by establishing coverage and fixing the candidate design. This phase implemented scripts/earnings_change_candidate.py without historical signal/return computation or changes to the existing engine/loader. The fixed score is quarterly common-income change divided by prior same-fiscal-quarter assets. It uses only backward-known fiscal pairs, supplied USD metadata and per-filing fxusd=1, with an exact180-day freshness cutoff. The earlier coverage diagnostic used integer-day age and could admit observations less than181days old; the executable feature enforces180days exactly. This is a disclosed timing precision correction before returns, not a tuned freshness window.

The target selector picks20highest-score longs and20lowest-score shortable names outside the long set,2.5%standaloneNAV each. Missing/nonfinite scores are excluded. Stable security ID sorts ties independently of input order. Fewer than40 finite names or fewer than20 eligible shorts yields explicit zero targets. Previously held instruments receive explicit zeros when not selected, matching the engine contract that absent IDs otherwise remain held. Ambiguous instrument/security mappings raise rather than silently duplicate exposure. These are target weights before execution and risk clipping; fill availability and actual net exposure are not established by this helper.

The monthly route helper consumes complete physical XNYS sessions including the preceding month and maps prior-month last close to next-month first open. A real installed-calendar test verifies November29 2024 early close18:00UTC -> December2 open14:30UTC and December31 close21:00UTC -> January2 2025 open14:30UTC. It rejects unordered/overlapping or naive timestamps. It does not validate that an externally supplied schedule is complete; the runner must supply the exchange calendar, not a price-derived calendar.
